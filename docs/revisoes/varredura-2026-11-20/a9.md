## Conferências feitas (com reprodução)
- **A6-01, confirmado.** No `teste_a9`: inseri um membro com aviso, apaguei o membro e, como `authenticated` com o token dele, `select texto from notificacoes` devolveu "Bloqueio de Fulano em LAGARTO"; `minhas_notificacoes()` recusou ("Você não tem acesso"). Política = `para = auth.uid()` e `authenticated` tem SELECT; a tabela está na publicação `supabase_realtime`. **Alcance corrigido:** avisos de Registros novos já não chegam (`avisar_registro` lê de `membros`); o que chega de novo são só os pessoais de `notificar()` (decisão de cadastro, comentário de tarefa, tratativa concluída). O grosso do vazamento é o histórico antigo: um moderador removido leva todos os avisos. Fica crítica pela régua (acesso indevido hoje).
- **A5-08, confirmado o mecanismo, prioridade derrubada para baixa.** `aviso_tira_id('Acordo (ID 2026) vence em 20/11/2026.', '2026', 'Ana Ano')` = "Acordo vence em 20/11/Ana Ano." Mas a troca só acontece quando o aviso já é daquele entregador **e** o código dele coincide com outra palavra ou número do mesmo texto. Os casos do a5 foram montados com fichas de ID "2026", "1500", "centro" e uma placa. Com códigos reais do app, risco distante e nenhum dado real afetado.
- **A11-01, confirmado no código, alta → média.** `leitor.js:49` dá preferência ao rótulo "Id" sobre o ID do endereço, e o campo vazio pega o valor vizinho. Porém o ID aparece num campo editável antes de gravar (`formularios.js:67`), os valores errados medidos são palavras óbvias ("Cliente") e a extensão ainda não está com a equipe. O A11-02 continua alto porque o ID errado ali parece válido.
- **A3-13, confirmado no código, alta → média.** Abertas e em andamento não têm limite. Mas os 577 itens são massa do a3: não há número real (o a10 ainda não recebeu os dados). Vira alta se a fase 2 mostrar mais de ~150 abertas.
